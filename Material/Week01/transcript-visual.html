為什麼現在學 AI？不是只為了多會一個工具

課程先談兩個問題：職涯如何改變，以及當答案隨手可得，教育還要培養什麼。

QUESTION 01

職涯：新手如何進入真實世界？

講者觀察到，一人搭配 AI 的產出，正在改變部分公司的用人與帶新人方式。學會調用工具之外，也要能組合跨領域知識，處理沒有標準答案的問題。

QUESTION 02

AI 賦能：答案之外還剩什麼？

如果拍照、輸入一個 prompt 就能拿到答案，學習不能只停留在交出答案；還要能判斷答案、提出問題，知道自己理解到了哪裡。

判讀界線：課中關於工作替代比例、訂閱費、大學年限與產業動向，包含講者觀察及二手引述，不是本頁獨立驗證的普遍統計，也不是休學或職涯決策建議。
講者的歷史類比：基礎建設之後，才是更廣泛的應用

課中把網路時代整理為「網路基礎 → 入口網站 → 新載體 → App 爆發」，再推想 AI 可能經過「AI 基礎 → 更普及的操作方式 → 新載體 → 應用擴張」。

這是類比與未來推測，不是確定的技術時程。講者也明說，目前還不知道普及性的 AI 作業系統會長什麼樣。

DURABLE SKILL 01

批判性思考

不要把「答案流暢」當成「答案正確」。問依據、看反例，回到領域知識檢查。

DURABLE SKILL 02

元認知

知道自己懂了什麼，也知道卡在哪裡。能指出缺口，比假裝全部看懂更有幫助。

DURABLE SKILL 03

成長心態與好奇心

願意多試一點、多問一個問題，不急著替自己的能力下結論。

DURABLE SKILL 04

一點點堅韌

接受不確定，也接受失敗。第一次看不懂，可以重新觀察、換方法再試。

  1. 觀察親眼看一次操作，檢查 AI 的回答。
  2. 反思問自己哪裡不懂、哪一步還能更好。
  3. 迭代改一個地方再做一次，記錄差異。

另一個重點是資訊的驗證成本：生成更快、更便宜，不代表來源更透明。課中因此把領域知識與判斷能力放在核心位置。

先分清楚：Token、ID、Embedding

它們是連續的步驟，但不是同義詞。Token 也不保證等於一個中文字或一個英文單字。

課堂切分示意

「我想開始」可能切成三個 Token

我TOKEN 1想TOKEN 2開始TOKEN 3

這是講者的示意；實際切法依 tokenizer 而定。空格、逗點、換行也可能單獨或連同其他文字形成 Token。

TOKEN

切出來的單位

例如字、詞片段或符號。先問「這串輸入被怎麼切」，不要只數看得見的字。

TOKEN ID

置物櫃的號碼

ID 用來索引，不是語意大小的刻度。課中以 2000 與 8000 為例：8000 不表示意義是 2000 的四倍。

EMBEDDING

對應的一組數值

從 ID 找到向量表示，讓模型能進行後續計算。它不是把 ID 當作有大小意義的單一數字。

地端與雲端：模型在哪裡計算？

講者用 Ollama 與本機 Qwen 模型示範「地端」：模型檔案與運算都在自己的電腦。雲端服務則把輸入送到服務端，計算後再傳回結果。

整理補充：可儲存成檔案的是模型權重等資料；實際使用還需要執行程式。不能把「模型是檔案」理解成只有檔案就會自行回答。

05

同樣幾個字，順序與前文會改變意思

Token 的向量還不夠；模型也需要位置資訊，以及和上下文互相參照的計算。

課堂例子 · 交換順序

狗 → 咬 → 人

現在是狗做出「咬」的動作。三個字沒變，但換順序後，誰做動作就不同。

Q · QUERY

我現在要找什麼？

用目前的查詢，尋找和這個位置有關的資訊。

K · KEY

哪些資訊和我相符？

把查詢與可用位置的 key 做匹配，形成注意力權重。

V · VALUE

要帶回什麼內容？

依權重組合對應的 value，形成上下文相關的表示。

比喻不能照字面套用。課中用排隊找同伴說明 Q、K、V。這不是模型真的在辨識人臉、判斷「心善」；在此處討論的因果式文字生成中，也不能偷看尚未產生的未來 Token。
想知道嚴格一點的版本？

Q、K、V 都是向量表示。注意力用 Q 與 K 的相容程度計算權重，再對 V 加權；不是只挑出一個標籤。原始 Transformer 解碼器以遮罩阻止位置關注後面的未知位置。

06

一次接下一步，不是一次寫好整篇

每產生新的 Token，上下文就變了，接著再計算下一輪。串流顯示的視覺速度，不等於每個畫面上的中文字都恰好是一個 Token。

整理者示例 · 不在此頁執行模型

從「我想喝一杯」開始

下面只示意「選下一步 → 接回上下文 → 再選下一步」。分詞與選字不是某個模型的實測結果。

STEP 1

先有上下文，才有下一步的分數。

輸入經過切分與模型計算，才得到候選 Token 的分數。

我想喝一杯
TEMPERATURE

調整分布的集中程度

固定原始分數時，較低的正溫度通常讓分布更集中；較高時較平坦。這不是「真實性」旋鈕。

TOP-K

留下幾名候選者

保留機率最高的 K 個候選 Token。它控制的是候選名單，不是一次輸出 K 個 Token。

TOP-P

看累積機率門檻

按機率排序，保留累積機率達到 p 的最小候選集合。不是「只保留單項機率大於 p」的 Token。

精確化補充：Top-p 的累積定義依 Hugging Face 官方文件補充，與課中口語說法區分。是否開放參數、預設值多少，取決於模型與介面；課中的數字不能直接當成所有模型的預設。
每次生成一定都隨機嗎？

不一定。抽樣會引入隨機性；greedy decoding 則選分數最高的候選。低溫或不抽樣都不等於保證正確。

不要把「某個 Token 被選中的機率」誤認為「這句話為真的機率」。前者描述輸出分布，後者需要另行查證。

最重要的使用態度：流暢，不等於正確

課程最後把焦點拉回使用者：AI 放大的不只是能力，也可能放大偏見、盲點與想被認同的需求。

早餐店 A

聽起來舒服

「怎麼又瘦了」

它說的是你想聽的話，所以你容易覺得「它最懂我」。

早餐店 B

聽起來不舒服

「怎麼又變胖了」

不順耳的回答也可能值得檢查，但不能因為難聽就認定它比較真。

兩邊都要核實。這個比喻不是要把「反駁我」當成正確標準，而是提醒：被認同的感覺，不能取代依據。

如果要的是建議，而不只是支持，

  1. 先辨識主張它是在說事實、給建議，還是在做推測？

08

把「看懂」變成三個小練習

沿用課中提議：觀察真實工具的差異，再用自己的話解釋。不要只記住名詞。

練習 01

看一次真實切分

在 Tiktokenizer 輸入同一句話，再加空格、換行，或換 tokenizer。記錄切法與 ID 如何改變。

練習 02

固定輸入，只改一個條件

到 Transformer Explainer 觀察候選分布與逐步生成。一次只改溫度或候選範圍，分清楚是什麼造成差異。

練習 03

用自己的話串起全流程

說清楚文字、Token、ID、向量、上下文計算與選字之間的關係。再解釋為什麼輸出流暢，仍然可能答錯。

自我檢查：這三題能不能回答？

1. 四個中文字一定是四個 Token 嗎？不一定；要看 tokenizer。

2. ID 比較大，語意就比較強嗎？不是；ID 是索引。

3. 下一個 Token 機率很高，整句就一定是真的嗎？不是；仍需檢查事實與推論。
