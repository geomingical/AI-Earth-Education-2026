code 06 // SCHEMA DECONSTRUCTION

一個 Skill 到底長什麼樣子？
極簡 4 大要素拆解

不要被技術名詞嚇到！為 AI 寫一個 Skill，本質上就是寫一個帶有「自我介紹註解」的普通函數。

1
Name（技能名稱）

清晰明瞭的識別符，例如 get_weather 或 send_slack_alert。

2
Description（功能描述 - 最關鍵！）

這是最重要的部分！AI 是讀取這段說明來判斷「現在這個問題該不該用這個 Skill」。說明寫得越好，AI 調用越準確。

3
Parameters（輸入參數格式）

規範需要哪些引數（如城市的字串、日期的格式），保證 AI 傳入正確無誤的數值。

4
Handler Function（執行函數實體）

真正發出網路請求或進行資料庫操作的 Python 或 TypeScript 程式碼。

help_outline 07 // COMMON QUESTIONS

初學者常見疑惑解答 (FAQ)

釐清概念邊界，避開新手在建構 Agent 時最常踏入的認知誤區。

Q1

Skill 和 Prompt 提示詞有什麼根本不同？

Prompt 是「思維的引導」，教 AI 用什麼角色或語氣思考；而 Skill 是「雙手的能力」，賦予 AI 實際去碰觸外部 API、抓取即時網頁或執行運算的能力。你可以把 Prompt 想成面試給員工的 SOP 守則，而 Skill 則是發給他的筆記型電腦與公務電話。

Q2

初學者該如何開始為 Agent 寫第一個 Skill？

非常推薦從「只讀型 API（例如公開天氣、匯率查詢）」開始練習！你只需要懂得基本的 Python 語法（寫一個簡單的函數），並透過像 LangChain、LlamaIndex 或 CrewAI 等開源框架掛上 @tool 裝飾器，10 分鐘內就能完成你的第一個 Agent 工具！

Q3

掛太多 Skills 會不會讓 AI 變笨或搞混？

會的！ 如果一次塞給模型 50 個 Skill，模型會因為 context 負擔過大產生「工具選擇困惑（Tool Selection Confusion）」。最佳實踐是：為特定任務專門掛載 3-7 個高相關性 Skill，或者使用階層式多 Agent 架構，由經理 Agent 將任務分派給擁有特定工具的專職 Agent。

Q4

讓 AI 自主執行操作（例如刪除檔案）安全嗎？

對於具備高風險或不可逆的動作（如扣款、發信、刪庫），標準做法是在流程中加入「人機協同審核（Human-in-the-Loop）」機制。AI 決定要調用該 Skill 時，先向人類發出確認彈窗，待人類點擊「核可」後才真正觸發執行。
